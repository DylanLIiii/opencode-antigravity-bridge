# agy 1.5.0 compatibility assessment

Assessed on 2026-11-04 against the local Linux `agy --version` = `1.5.0`.
The initial assessment used control-plane probes without model generation.
Implementation and subsequent real generation checks are recorded below.

## Conclusion

No mandatory transport migration was found in the verified control-plane paths.
The bridge already uses `agy acp`, protocol version 1, cached CLI credentials,
and the IDE MCP flags documented by Google. Keep that architecture.

Image input and ACP model/thinking configuration have now been implemented.
Real image inference, a client tool round trip and cross-process resume passed.
Quota reporting, live dynamic tool lists, cancellation and long-running tools
still need separate 1.5.0 validation; do not claim blanket compatibility.

## Primary sources

- [Official CLI ACP overview](https://antigravity.google/docs/cli/acp/).
- [Official full ACP guide](https://antigravity.google/docs/ide/extensions/acp/):
  protocol, authentication, images, model/thinking pickers, session operations,
  client restrictions on third-party models, IDE MCP and worker-process flags.
- [Official changelog](https://antigravity.google/docs/changelog/): the retrieved
  portion containing CLI releases listed 1.4.12 as its newest CLI entry. The
  local `agy changelog` also began with 1.4.12. Neither supplied 1.5.0-specific
  release notes during this investigation; do not treat every current ACP
  feature as newly introduced by 1.5.0.
- Local executable: `agy --version`, `agy --help`, `agy acp --help`, plus live
  JSON-RPC responses from `initialize`, `session/new`, `session/set_model` and
  `session/resume`.

## Verified behavior and implications

1. **Transport remains compatible.** The executable exposes `acp` in its public
   help. `--agent`, `--log-file`, `--ide-mcp-port` and `--add-dir` are accepted
   ACP flags. The live initialize response returned protocol version 1 and
   agent version 1.5.0. The existing startup arguments need no demonstrated
   change. This does not verify model-facing IDE tool registration.

2. **Session instructions and reuse remain available.** Initialize advertised
   `_meta.antigravity.systemPrompt.append` and session resume. A session with
   the bridge-style isolated agent and system-prompt append was created;
   changing to Gemini and Claude model IDs succeeded; `session/resume` succeeded
   in that same ACP process. This probe did not verify cross-process recovery
   of a conversation containing actual model turns.

3. **Current model routing still works.** The live session still returned
   effort-suffixed IDs such as `gemini-4-argon-medium` and
   `claude-opus-5-5-low`. The existing provider discovery returned the expected
   grouped families. Keep `session/set_model` as the compatibility path.
   `clientInfo.name = "zed"` still exposed third-party models; the official
   guide confirms that their availability depends on the ACP client.

4. **Images are now advertised to this client.** The live response contained
   `promptCapabilities.image: true`, `embeddedContext: true`, and `audio: false`.
   Google's current guide explicitly describes image attachments. The bridge's
   `blockText()` rejects user image blocks and `Proc.#runTurn()` always sends a
   single text block, so the bridge does not expose this advertised capability.
   The earlier 1.4.12 handoff recorded no image capability; actual image
   comprehension on 1.5.0 remains untested.

5. **Separate configuration options are exposed.** `session/new` returned
   `configOptions` with `model`, `thought_level`, and `mode`. The selected
   models offered low/medium/high thinking levels. Google's guide describes
   additional thinking levels where available. Consuming these options would
   reduce dependence on parsing model-ID suffixes, but is optional while the
   existing IDs work. Setting configuration options was not probed.

6. **Cached sign-in remains the correct path.** Google's guide explicitly says
   that ACP reuses CLI credentials. The initial `Authentication required`
   response was traced to the local wrapper's unavailable proxy at
   `127.0.0.1:7890`, preventing credential refresh. With a temporary child-only
   proxy override, the session operations succeeded without an ACP
   `authenticate` call. No persistent proxy or sign-in configuration was changed.

7. **Quota compatibility is unresolved because of upstream network failure.**
   Existing `fetchUsage()` attempts timed out at the default 15-second and
   maximum 18-second budgets. A separate `/usage` probe with a larger bounded
   deadline failed during the Google eligibility `loadCodeAssist` request with
   EOF, before a successful quota report. There is no observed successful 1.5.0
   payload on which to base a parser change. Do not increase the bridge timeout
   past Magpie's host deadline or change the parser on this evidence alone.

## Recommended adjustment order

1. Add a repeatable opt-in 1.5.0 integration check and update the documentation
   with precise validation scope. The existing fake CLI identifies as 1.4.12;
   add representative capability/configuration fixtures without implying that
   changing the fake version proves real CLI compatibility.
2. Add image support behind negotiated `promptCapabilities.image`, mapping
   supported Anthropic image sources into ACP image blocks. Cover initial and
   continued prompts, history replay after a restart/mismatch, model capability
   differences, and actual image comprehension before advertising support.
   Correct the current diagnostic that says ACP accepts text only.
3. Optionally use ACP model/thinking configuration options, retaining the
   existing `session/set_model` route for older versions and verified IDs.
4. Recheck live text/thinking streaming, usage fields, client tool round trips,
   dynamic tool lists, cancellation, long tools, and cross-process resume.
   Retain the current private `nc` shim and MCP handshake workaround until a
   direct replacement is verified. The official guide still documents
   `--ide-mcp-port` and its `nc` requirement; HTTP MCP configured by the editor
   requires `--process-per-session`, which is a different path from this bridge.
5. Retry quota reporting on a stable Google API connection, then compare the
   actual successful report with `parseUsageReport()` before making changes.

## Existing regression checks

`npm test` passed: **14 quota tests and 170 smoke checks**. These use a fake agy
and the real bridge MCP helper. They verify current bridge behavior, not real
1.5.0 generation, model-side tool visibility, image input, or quota API health.

## Implementation and validation

- `index.mjs` maps inline base64 PNG/JPEG/GIF/WebP to ACP image blocks, preserving
  order and images in new prompts, continuations and history replay. It checks
  the server's image capability before returning a stream. URL images, malformed
  data and user documents remain explicit HTTP 400 errors. Image cache metadata
  does not change conversation identity, and persisted state contains only hashes.
- Model and thinking selection now prefer `session/set_config_option` using
  the advertised select IDs, categories and values. Grouped options and
  `config_option_update` notifications are handled. Model changes refresh
  dependent thinking options. Legacy selection is retained when configuration
  is absent or the server returns Method not found; real errors stay visible.
  The host's initial model directory still comes from `agy models`.
- `test-smoke.mjs` has a representative 1.5.0 fixture and explicit legacy cases.
  The final Node suite has **208 smoke checks and 14 quota tests**. Bun is not
  installed in this environment; the new cases were not verified on Bun.
- `test-integration.mjs` / `npm run test:integration` is opt-in via
  `AGY_BRIDGE_INTEGRATION=1`, uses real quota, and isolates bridge state in a
  private temporary directory. On real Linux agy 1.5.0 with
  `gemini-3.8-flash`, a red test image was recognized, exactly one native client
  tool call completed, text and token usage were received, and a second Node
  process resumed the same agy session while retaining the image and tool-result
  memory and accepting a different thinking level. No thinking summary was
  emitted by that model in the checked first turn.
- The same full integration check also passed with `gemini-4-argon`: image
  comprehension, one native MCP call, final text/token usage, and cross-process
  resume preserving image/tool context while changing thinking level. Its first
  turn also emitted no thinking summary. An earlier Argon attempt exceeded the
  60-second ACP startup budget. A subsequent staged probe completed initialize,
  created a session in approximately 15 seconds and applied model/low/high
  configuration changes in milliseconds; the full retry then passed. The
  earlier timeout was not reproduced and its cause remains unresolved. No
  production timeout was increased. The resumed final Node regression run again
  passed all 208 smoke checks and 14 quota tests; syntax, npm packaging and
  whitespace checks also passed.
- A final `auth.usage()` retry with the existing 18-second maximum returned
  `agy usage query timed out.` after approximately 18 seconds, with no quota
  windows. Successful ACP inference does not establish that the separate usage
  command is healthy. Quota payload compatibility remains unverified; the
  parser and host deadline remain unchanged.
- A separate real 1.5.0 control-plane probe successfully used
  `session/set_config_option` to change model to Claude Sonnet, select high
  thinking, switch to Gemini Flash and select low thinking. It confirmed the
  request fields `sessionId`, `configId`, `value` and updated `configOptions`.
- [ACP configuration protocol reference](https://github.com/agentclientprotocol/agent-client-protocol/blob/main/docs/rfds/session-config-options.mdx).
- [Magpie host model field mapping](https://github.com/yetone/magpie/blob/main/internal/plugin/host.js)
  confirms `capabilities.input.image` is how image input reaches the host.

Investigation scripts and raw outputs remain in `/tmp`; the reusable integration
check is in the repository and is excluded from the npm package.
