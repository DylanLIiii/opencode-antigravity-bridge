01
多账号Accounts

一个模型 ID，多个账号，由 Magpie 来选。One model ID, several accounts, chosen by Magpie.

每个 Google 账号在 Magpie 中独立成行，共用不带前缀的模型 ID。首选、启用/关闭和账号路由规则都用 Magpie 自带的；会话、进程和额度按账号隔离。直接用 OpenCode 时，仍可写 <账号>/<模型id>。 Each Google account is its own Magpie row, sharing ordinary model IDs without prefixes. Preference, on/off switches and routing rules are Magpie's own; sessions, processes and quota stay per account. Direct OpenCode use can still write <account>/<model-id>.

Magpie's own routing rules decide in practice. Account names and models are examples; available models depend on what each account and agy version actually offer.

    精简 promptLean prompt

    去掉 agy 自带的 8K 编码 prompt。Drop agy's built-in 8K coding prompt.

    精简 agent 默认开启（AGY_BRIDGE_MINIMAL_AGENT=0 可关闭）。客户端自己的 system prompt 和工具目录才是权威来源；指令每个会话只安装一次，每轮只发新增消息。 The minimal agent is on by default (AGY_BRIDGE_MINIMAL_AGENT=0 turns it off). The client's own system prompt and tool catalog are authoritative; instructions are installed once per session and each turn sends only the new message.

    03
    缓存命中Caching

    前缀稳定，缓存才有机会。命中与否由 Google 决定。A stable prefix gives caching a chance. Google decides whether it hits.

    请求只追加不改写，便于 Google 后端复用前缀。在历史 Argon 样本中，每轮约最后 2,049 个 token 不从缓存读取，因此 prompt 越大，比例越高。下方示意按这个推断计算。 Requests only append, so Google's backend can reuse the prefix. In historical Argon samples, about the last 2,049 tokens of each turn were never read from cache, so the share grows with prompt size. The illustration below applies that inference.

    真正的客户端工具Real client tools

    客户端工具以 MCP 原生工具出现：并行、多轮、长耗时，每个调用只执行一次。没有文本约定 hack。Client tools appear as native MCP tools: parallel, multi-round, long-running, each run once. No text conventions.

    会话复用与续接Session reuse and resume

    每轮只发新增消息；空闲、淘汰或重启后按哈希快照（不存明文）session/resume。历史改写时按预算重放。Each turn sends only the new message; idle, evicted or restarted sessions resume from a hashed snapshot (no message text). Changed history replays within budget.

    流式 · 思考 · 图片Streaming · thinking · images

    文本与思考摘要流式输出；内联 PNG/JPEG/GIF/WebP 输入需要 agy 声明图片能力（1.5.0 起）。Streamed text and thought summaries; inline PNG/JPEG/GIF/WebP input requires agy to advertise image support (1.5.0+).

    用量看得见Observable usage

    区分实际输入、缓存读写、输出与思考量；Magpie Usage 页显示订阅额度（仅展示）。Separates actual input, cache reads/writes, output and thinking; Magpie's Usage page shows subscription quota (display only).

    隔离而不越权Isolation without bypass

    不读取全局 MCP 配置；agy 的权限请求一律拒绝，操作发生在客户端侧。No global MCP configuration is read; agy permission requests are rejected, and actions happen client-side.

    不放大重试No retry amplification

    已提交的 Prompt 不会因客户端重试再次交给 agy，返回 prompt_outcome_unknown。A submitted prompt is not resent on client retry; it returns prompt_outcome_unknown.

    06
    边界Boundaries

    说清楚它不保证什么。What it does not guarantee.

    • 型号按账号实际探测列出，不保证全部 Gemini / Claude / GPT-OSS 可用。Models are listed from each account's probe; no model family is guaranteed.
    • 走官方 CLI 不等于保证账号不受限制，也不排除 Google 政策变化。Using the official CLI does not guarantee against account restrictions or Google policy changes.
    • 缓存由 Google 后端决定；数字是历史样本，不是承诺。Caching is Google's decision; the figures are historical samples, not promises.
    • 额度窗口仅展示，不会在耗尽时自动停请求。Quota windows are display-only and do not stop requests.
    • 命名账号需要 agy 支持 --gemini_dir 和文件 token；WSL 模式只支持默认账号。Named accounts need --gemini_dir and file tokens; WSL mode supports only the default account.
    • Windows 已有自动化测试，尚未完成实机验证。Windows has automated tests; real-host verification is pending.
