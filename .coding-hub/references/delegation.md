# 项目委派契约

父会话先读 [项目 Coding Hub](../SKILL.md)，为每个任务确定角色、路由、范围与依赖。
子任务不继承父对话，所需信息必须写入简报；不要要求它“参考上面的讨论”。

```text
项目：opencode-antigravity-bridge
角色 / 难度：<Worker / Craft 等>
执行：OpenCode；<已核对的实例及完整模型 ID>
目标：<具体缺陷或行为变化>
依据：<Issue、复现、日志或外部来源；区分事实与假设>
工作区 / 分支 / base：<工具实际分配的 checkout 和 revision>
范围：<允许修改的路径；已有改动及归属；依赖是否已经提交>
完成标准：<可观察结果、必要检查、预算和停止条件>
约束：保留已有工作；不得再 spawn、委派、开线程或另启 Agent。
参考：<目标机器可读的项目 Skill/reference 路径；必要时内联>
返回：<父线程真实 link 或终端地址；结论、文件、测试和遗留事项>
```

候选技能按名称在目标机器发现，再传可读路径和用途。不写死 env.dev checkout 或父机器的路径，
不自动安装技能。简单 Explore / Librarian / Oracle 任务直接写清只读范围和返回证据即可。

## Worker

- 先读工作区说明与 diff，按已有实现模式修改任务范围。实现留在分配的分支，不搬到其它 checkout。
- 不新增写手或子任务。需要独立专家时把问题和证据交给父会话。
- 先完成可独立执行的工作；遇到真正缺失的信息或权限，说明依赖，不把超时当作失败重派。
- 依据 [项目验收](validation.md) 和本次完成标准运行适当检查，保留命令、结果和对应 revision。
- 不用弱化测试断言、取消安全边界或覆盖其它修改来“修绿”测试。
- 完成后回报变化、验证和剩余事项。没有跑过的检查明确写未验证。

## Reviewer

- 父会话提供明确 base/head 或 diff、完成标准、已有证据和待确认风险。
- 只读审查；每个发现写清位置、触发条件、影响与证据，区分缺陷和验证不足。
- 不改实现、不合并、不推送、不再委派。没有发现时也说明审查范围和局限。
- 重审由父会话启动新任务并附前次发现及修复，不能让旧任务隐式扩大范围。

## 返回与持久产物

小任务直接返回，不要求创建报告。需要独立报告时由父会话指定项目外的持久目录，
保留旧报告，临时目录不作为唯一产物位置。跨机器结果注明机器与绝对路径。
PM 记录由父会话维护，子任务不编辑全局台账。

子任务涉及 PR 时遵循宿主关联规则，不自行监视。最后一行采用：
`PR <full URL>, head <SHA>, checks and reviews <state>`。
未涉及 PR 的任务不虚构 PR、SHA 或检查状态。
